# Book recommendations and selected-book conversion

Recommend the books that best fit the user's question, whether or not they are in Answer With Books. Outside recommendations may dominate the answer. Check the catalog to identify what is already available and avoid duplicate processing, not to constrain or prioritize the reading list. Respect an explicit catalog-only or private-library request. Distinguish catalog evidence actually read from outside descriptions or excerpts; never imply an outside title has already been processed.

### Explain how the shortlist was chosen

Make the filtering criteria visible before asking the user to choose. Rank by direct fit to the user's question, the contribution of each book, and the user's stated reading preferences. Remove weak matches and books that duplicate the same contribution. Catalog membership and availability of a free download do not establish quality.

- For a history or foundations question, or a preference for established classics, favor foundational works and historical explanations. Keep recent practical guides as optional additions when they serve a distinct purpose. Do not apply an arbitrary publication-year cutoff or assume older means better. Show original publication years when comparing eras, distinguishing them from edition dates.
- If the user wants widely recommended or influential books, verify that assessment using relevant scholarly sources, course reading lists, or independent authoritative recommendations. Do not invent recommendation counts or treat a single search ranking as consensus. Say when a shortlist reflects relevance judgment rather than a measured popularity filter.
- Give a short reason for including each title and explain a consequential exclusion, such as leaving out a recent software-team manual when the user wants the historical origins of specialization. Preserve titles the user has already selected.

### Present an interactive selection response

After presenting a book shortlist, use the host's native multiple-choice question feature when available, rather than ending only with "Which books would you like?" In this host, use `request_user_input_async`; use another choice tool only when it is available and permitted in the current mode. This is a reading preference question, not authorization to upload.

- State the chosen filters in the question or nearby explanation. Offer a few clear choices that show actual titles and how their coverage differs, with the recommended choice first. Carry forward previously selected books; do not make the user select them again.
- If the host supports only single-choice input, offer explicit reading sets (for example, the selected book alone or the selected book plus one complementary title). Do not imply that checkboxes or multi-select exist. Permit a custom combination through the host's free-text response. If there is no native choice tool, use a compact numbered selection instead.
- Wait for the user's selection before doing dependent acquisition or processing. A highlighted default or silence is not a submitted choice. Continue independent work, but do not replace unanswered preferences with an assumed selection. For an asynchronous choice tool, keep the turn active with short interruptible waits that wake on user input; do not immediately finalize the turn or replace the native question with follow-up links. Follow the host's progress-update requirements while waiting.
- Once the set is selected, offer both source routes in the same native processing choice: "Upload my copy", "Find a downloadable copy", and "Keep this as a reading list". Name the selected titles and state in the question that either source route creates private summaries and reusable skills, sends source text to Answer With Books and its AI provider, and installs skills only when installation is included in the request. User uploads are a first-class route, not a fallback after web search fails. Follow the host tool's authorization rules; if it cannot request approval, ask this processing question in ordinary chat. Reuse the user's existing source choice and conversion approval; do not ask them to repeat either. Selecting a title for discussion alone does not authorize conversion.
- For "Upload my copy", invite the user in ordinary chat to attach a supported file (for example PDF or EPUB), or provide an accessible local file path. The native question selects the route; it is not a file picker, and `request_user_input_async` must not be used to request file uploads. Wait for the actual file or path before processing; choosing the upload route does not mean a file has arrived. Use the supplied edition and skip web acquisition. If the user already supplied a file and requested conversion, proceed directly without a recommendation or source-selection detour. If a file is inaccessible, explain what is missing rather than silently substituting a web copy.

After the user accepts, carry the workflow through to results:

1. Resolve each selected source through the user's chosen route. For an uploaded attachment or local path, use that file and retain its filename and source identity. For web acquisition, find and download a full copy from a publisher, author, authorized library download, or public-domain source, and retain its URL. Prefer PDF or EPUB; accept the runtime's other supported formats. Verify the title, author, edition, and completeness for either route; a preview or an existing summary is not a full book. Do not bypass DRM or make an unapproved purchase. If a selected source is unavailable, explain that specific gap and request the missing file or path in ordinary chat while continuing with other available, approved books.
2. Save sources in a private working directory outside version control. Check that the files contain readable book text; perform supported OCR when necessary or report the extraction limitation. Reuse an existing ready account book only if it matches the selected source and requested output.
3. Connect the user's account through `login` when needed, then run `upload FILE --process-file --mode full` for each new selected source. The full workflow approval covers using the supplied files or acquiring the chosen web copies and uploading those sources; do not ask again at each step. Use `--process-file` so a public title match does not substitute an editorial digest for the requested full-source conversion. For missing extraction dependencies, use the pinned release CLI documented below.
4. Follow each returned job with `status`, using spaced checks and concise progress updates until it is ready, fails, requires user action, or stops making progress. Preserve job IDs and resume existing work; do not resubmit successful files. A queued upload is not a completed result. If continued progress is blocked, report the exact stage and what is needed instead of claiming completion or promising an unscheduled later response.
5. Inspect the generated digest, chapter methods, citations, and any review findings. Export the book-and-skill package with `download BOOK_ID`. When local installation was included in the user's approval, run `library install-book BOOK_ID`, read the installed chapter references, and verify a question related to the user's original purpose against its cited source. Preserve the review and activation requirements below; never pre-accept findings the user has not seen.
6. Return the actual results for each selected book: a concise source-grounded summary, its private book link, the exported summary/skill package or installation path, and an example of using its methods on the user's task. Clearly identify any unavailable, failed, or unfinished book. Report the actual installed skill name if installed; otherwise call it an exported skill, not an installed one. Do not finish a successful conversion with only instructions, source links, or job IDs.

When explaining capabilities, include reading and applying existing books, comparing book methods, accepting user-uploaded files or acquiring selected web sources and processing either into linked summaries and skills, invoking installed book skills in later work, and updating or exporting private books. Distinguish available functionality from actions completed for this user.
